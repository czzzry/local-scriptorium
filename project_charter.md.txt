# Local Scriptorium Project Charter

## Mission

Build a local-first AI research assistant that runs on my current Mac, uses a small local source corpus, retrieves relevant source passages, and generates grounded answers with source IDs.

The purpose of the project is to learn the practical implementation pattern behind local/edge-style AI inference: where inference happens, what data stays local, how retrieval supports grounded answers, and how output quality can be evaluated.

## MVP Goal

The MVP will demonstrate the following loop:

source files → chunks with source IDs → retrieval → local model inference → grounded answer → evaluation

The MVP is complete when I can ask a question about the local source corpus and receive an answer generated by a local model, using retrieved source chunks, with source IDs and an uncertainty section.

## MVP Scope

The MVP will include:

1. A local model running on my current Mac.
2. A small corpus of 3–5 clean text/markdown source files.
3. Source metadata for each file.
4. Chunking of source files into stable source-labeled passages.
5. Basic retrieval of relevant chunks for a user question.
6. A grounded answer prompt that forces the model to answer from retrieved chunks.
7. Answers that include:
   - answer
   - evidence
   - source IDs
   - uncertainty
   - what the sources do not establish
8. A small evaluation set of at least 15 test questions.
9. A short memo explaining what this taught me about local/edge-style inference.

## Model and Tooling Approach

The exact local model will be selected during the local inference baseline phase.

The MVP will use the simplest reliable local inference stack available on my Mac, likely Ollama or an equivalent local model runner.

QVAC/Tether tooling is relevant to the broader learning goal but will not block the MVP. QVAC will be treated as an MVP+1 spike or comparison after the core local inference/RAG loop works.

## Target Corpus

The initial corpus will consist of 3–5 short, clean source files rather than full books.

Likely source types:

- personal notes on Christopher Dawson
- Paul Johnson chapter summaries
- Augustine notes or excerpts
- notes on Jung, Campbell, or Girard
- one short public-domain excerpt if useful

Full-book ingestion, scanned PDFs, OCR, and large source libraries are out of scope for MVP.

## Success Criteria

The MVP succeeds if:

1. A local model runs on my Mac.
2. The source corpus is stored locally.
3. Source files are split into chunks with stable source IDs.
4. A user question retrieves relevant chunks.
5. The local model generates an answer using those chunks.
6. The answer includes source IDs.
7. The answer distinguishes evidence from interpretation.
8. The answer includes uncertainty or says when the sources are insufficient.
9. At least 15 evaluation questions are tested.
10. The project has a short case-study memo explaining architecture, tradeoffs, limitations, and next steps.

## Non-Goals for MVP

The MVP will not include:

- true distributed edge deployment across multiple devices
- QVAC as a required dependency
- cloud deployment
- polished UI
- mobile app
- login/authentication
- OCR or scanned PDF processing
- fine-tuning
- multi-agent workflows
- automatic Jira integration
- production-grade security
- GPU purchase or new hardware

## Learning Goals

By completing the MVP, I should be able to explain:

1. What local inference is.
2. How local inference differs from cloud inference.
3. Why local inference is relevant to edge AI.
4. What data stays local in this prototype.
5. How RAG supports grounded answers.
6. Why source chunking and retrieval quality matter.
7. Where local models perform well or badly.
8. How to evaluate AI answers beyond vibes.
9. What would need to change for a real company deployment.
10. What belongs in MVP+1.

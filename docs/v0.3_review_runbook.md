# v0.3 benchmark review runbook

This runbook is intentionally separate from the corpus build. The question file remains `candidate` until a blinded second pass and adjudication are complete.

## 1. Build the full review packets

```bash
for offset in 0 25 50 75; do
  batch=$((offset / 25 + 1))
  python3 scripts/export_question_review_packet.py \
    --questions data/evaluation/late-antiquity-core-questions-v2.candidates.json \
    --corpus outputs/generated/packs/late-antiquity-core-v1/corpus.v1.json \
    --output outputs/generated/packs/late-antiquity-core-v1/review_packet_$batch \
    --offset "$offset" --limit 25 --review-id "late-antiquity-review-$batch"
done
```

Each packet is validated before review. The reviewer reads only the packet and the project-local `review-classics` skill. It must return a schema-valid second-pass result with no expected answers, original labels, split information, ranks, scores, or prior reviews.

## 2. Validate each result

```bash
python3 .agents/skills/review-classics/scripts/validate_result.py \
  outputs/generated/packs/late-antiquity-core-v1/review_packet_1 \
  /path/to/review-1.json
```

Repeat for all four packets. Results are immutable second opinions; they do not rewrite the question file.

## 3. Reconcile

Create a private control file containing the first-pass decisions, then run:

```bash
scriptorium review reconcile \
  --control /path/to/control-1.json \
  --packet outputs/generated/packs/late-antiquity-core-v1/review_packet_1 \
  --result /path/to/review-1.json \
  --output outputs/generated/packs/late-antiquity-core-v1/reconciliation-1.json
```

Material disagreements remain unresolved until a human adjudication record supplies an explicit `accept` or `exclude` decision. Translation-sensitive, authorship, chronology, original-language, and contested-doctrine cases should be routed to specialist adjudication or excluded.

## 4. Promote only reviewed items

```bash
scriptorium review accept \
  --questions data/evaluation/late-antiquity-core-questions-v2.candidates.json \
  --reconciliation outputs/generated/packs/late-antiquity-core-v1/reconciliation-1.json \
  --reconciliation outputs/generated/packs/late-antiquity-core-v1/reconciliation-2.json \
  --reconciliation outputs/generated/packs/late-antiquity-core-v1/reconciliation-3.json \
  --reconciliation outputs/generated/packs/late-antiquity-core-v1/reconciliation-4.json \
  --adjudication data/reviews/late-antiquity-core-adjudications.v1.json \
  --output data/evaluation/late-antiquity-core-questions-v2.accepted.json
```

The command exits non-zero and leaves items as `candidate` when coverage or adjudication is incomplete.

## 5. Run the release audit

```bash
python3 scripts/release_audit_v3.py \
  --register sources_public/source_register.v2.json \
  --pack data/packs/late_antiquity_core.v1.json \
  --questions data/evaluation/late-antiquity-core-questions-v2.accepted.json \
  --review-policy data/reviews/review_policy.v1.json
```

Only a `ready: true` result permits release claims. AI agreement is procedural consistency evidence, not classics scholarship or scholarly validation.

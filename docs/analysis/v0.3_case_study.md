# Local Scriptorium v0.3 case study

## The implementation boundary

The engineer owns the reproducible surfaces: source-register validation, deterministic normalization, canonical passage identifiers, chunking, indexing, retrieval, CLI behavior, schemas, checksums, review blinding, staleness, reports, and release gates.

The corpus owner or client owns the meaning surfaces: which editions are in scope, whether a translation is legally reusable, what user tasks matter, whether a candidate question is worth retaining, and whether a disputed interpretation needs a specialist.

The system can generate question candidates from the corpus without client-written prompts. That is an engineering convenience, not authority. A candidate becomes an accepted benchmark item only after protocol review and, where needed, human adjudication.

## Why canonical passages precede chunks

Questions cite stable edition-level passages. Retrieval chunks are experiment-specific derived artifacts. This prevents chunk-size tuning from silently rewriting benchmark truth and makes every answer traceable to author, work, translator, edition, and source location.

## What the evaluator can and cannot claim

The project-local `review-classics` protocol creates a blinded second-pass AI review with explicit independence levels, forbidden fields, checksums, and reconciliation. I1/I2 agreement is procedural evidence of consistency. It is not proof of classics expertise, scholarly consensus, or gold-standard truth. Translation-sensitive, philological, chronology, authorship, and contested-doctrine cases are routed to external adjudication or excluded.

## Interview-ready explanation

> I treated the RAG system as an evaluation laboratory rather than a chatbot demo. I separated source rights and edition provenance from ingestion, created canonical passage anchors before chunking, generated a held-out question blueprint, and made the review process blind and auditable. The system refuses to release a nine-source corpus when one edition is incomplete, and it labels AI review as procedural rather than scholarly. That fail-closed behavior is part of the product, not an afterthought.

## Current honest status

The nine-source development pack is now runnable with the original MacKenna volumes I–IV covering Enneads I–V. The release remains gated only by benchmark review, reconciliation, and adjudication. No README metric should imply that candidate questions are validated results.
